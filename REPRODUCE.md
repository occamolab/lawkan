# REPRODUCE.md — LawKAN: reproduction guide

How to regenerate the reported numbers and the vector figures produced from dumps
from the released code and public data. TikZ figures (Figure 1, A10, A11) are inline;
the 11 branch probes X37–X61 are summarized in Appendix K and the experiment plan
(the public prediction log has the 119 rows through X36). The experiment harness lives
in `repro/run_all.sh`; dumps go to `repro/json/` and the canonical dump per block is
pinned in `repro/canonical.json` (never resolve by "latest filename").

Reference machine: RTX 2080 SUPER + 4 CPU cores (see wall times below). The synthetic core
was recorded on GPU `float32`; the applied and revision blocks on CPU `float64`. The portable
reference path runs the synthetic core on CPU `float32`; a CPU-vs-GPU calibration on E16/E22
agrees within `<=0.005` per seed (largest mean delta `0.0011`; the table tolerance is `0.006`),
and no paired-test significance decision or win/parity ordering changes. The gyroscope parity
cell (X6, a-short) is likewise unchanged: LM 0.588359 vs LawKAN 0.588583 (CPU) and 0.588389 (GPU),
a gap of at most `2e-4 deg`. `repro/registry.json`
records the reference device/dtype per block; `repro/run_registry.py` enforces the requested
device (`--mode reference|gpu|smoke`) and logs the dtype used by each block.

## Quick start

```bash
# preflight (use --strict to fail on missing data vars)
python repro/doctor.py --strict

# full headline regeneration on the CPU reference (overnight; GPU optional: --mode gpu)
python repro/run_registry.py --tier headline --mode reference

# fast sanity that every headline block starts and dumps (minutes)
bash repro/run_all.sh headline-smoke

# mechanical JSON -> markdown tables (reads canonical.json)
python repro/make_tables.py

# paper-number checker (curated headline numbers vs the canonical dumps)
python repro/check_numbers.py

# manifest checker (every canonical dump exists and is tracked)
python repro/check_canonical.py

# registry-driven runs (tiers; device preflight; data env vars)
python repro/run_registry.py --tier headline --dry-run
python repro/run_registry.py --tier headline --mode reference
python repro/run_registry.py --only x46,x61 --mode reference

# notebooks (optional; no outputs are committed)
# see examples/README.md
```

`run_all.sh stageN` targets:

- **1** synthetic core; **2** IMU/gyro (X5-X9); **3** expansion (E20-E24); **4**
  state/component; **5** theorems; **6** three-platform X10; **7-8** phase-2.
- **9** MUKCa socket family (MK1: KUKA/Panda/Kinova 10 seeds, FR3 unit, cross-view);
  **10** ABB RobotCali (RC1, 10 seeds).
- **11** competitors/diagnostics (X6b, X7 vqf, X16 isolated); **12** appendix
  diagnostics (G2a/G2bc/G3/G4, X17, S8).
- **13** validity package (X18/X18b coning, X19 tau-psi, X20/X21 friction, POOL).
- **14** revision round (X22-X36: learned baseline, capacity/locality of the correction);
  **15** branch (X37-X61: convergence, socket heads, pole/EMA/geo).

Registry tiers: `smoke` (minutes), `headline` (Tables 1-5, Figures 2-4), `full`
(everything, including the branch and derived statistics). See `repro/registry.json`
for the block -> script -> paper-item map.

**ABB RobotCali is external data.** The published numbers are checked against the
pinned canonical dumps without the raw file; end-to-end runs of `RC1_robotcali.py`,
`X36_recount_socket.py` (ABB rows), `X41_classical_ref.py` and `X43_abb_lm.py` require
the xlsx. It has no redistribution license, so it is not in this repository. The expected
file has one sheet with columns `x,y,z,q1..q6,L` and the checksum above. `X43` is a
diagnostic only (its canonical note says the LM fit is unstable and not used as evidence).

## CPU reference run

`repro/json/cpu-reference/` holds the portable CPU headline run (reference device `cpu`).
`python repro/check_cpu_reference.py` verifies it against the curated paper-number list:
all checks covered by that run match (the remaining checks belong to full-tier blocks not
in the headline tier). The CPU/GPU calibration on E16/E22 and X6 is recorded above.

## Dumps and provenance

- Self-dumping scripts use `repro/dump.py`: dumps are dated, carry `_meta`
  (git HEAD, date, seeds, args), and `--quick` runs get a `-smoke` suffix so they
  can never overwrite a canonical dump.
- Superseded dumps live in `repro/json/_stale/` and are never cited.
- `repro/canonical.json` is the single source of truth for table/number tools;
  `repro/check_canonical.py` verifies every entry (exists on disk + tracked by git).
- The X19 verdicts are recovered from the archived training log
  (`repro/provenance/x19_full.log`) plus the canonical `g2bc_fig` dump, because the
  original X19 aggregation crashed after training; `X19_recover.py` is the producer of
  the canonical `x19` dump.

## Known deviations

- `x7cal` = `X7_robot_calibration.py` (stage2, bench calibration);
  `x7vqf` = `X7_vqf_reference.py` (stage11, VQF AHRS reference).
- MUKCa's own calibrated URDFs are reference KPIs under **their** protocol; the
  paper's socket numbers are our held-out RMS (see paper Appendix F).
- Seeds: MK1 front trio and RC1 run at 10 seeds (P-D); MK1 FR3 unit and the two
  KUKA cross-view sessions at 5; X10 at 10 seeds (random split) and 5 (cluster
  split, P-E).
- Figure 3's curves and the Table 3 two-slot/MLP rows come from the 5-seed `x7bench`,
  `x35` and `x22` dumps (N=20..80); `g2bc_fig` is the earlier Fourier-head run and
  `g2bc` is the registered P-D 10-seed replication (N=60/80).
- The shuffle control (`mk1c`) ran 5 seeds; its real-constraint comparison uses the
  10-seed `mk1` values (0.19/0.36 mm). The 5-seed ABB dump `rc1_5seed` remains pinned
  as the source of the stored P-RC verdict values in the supplementary prediction log;
  the paper's §5.4 prose now quotes the 10-seed canonical `rc1` (1.70 vs 1.83 mm at
  N=40; GN 1.41/1.20/1.14 mm).
  Tables 4-5 use the 10-seed `mk1` and `rc1` dumps (plus the X36 socket recount).
